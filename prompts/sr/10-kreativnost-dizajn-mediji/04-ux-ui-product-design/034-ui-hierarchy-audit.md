# AUDIT UI HIJERARHIJE

Glavni cilj:

> Sprovedite production-grade workflow za "Audit UI hijerarhije", sa jasnim briefom, pravilima sistema, review kriterijumima i planom iteracije.

## 1. KONTEKST
Define audience, objective, medium, deliverables, references, constraints, accessibility, rights/licensing, timeline, budget and approval owner.

## 2. DOMAIN STANDARD
Product design should optimize user goals, information hierarchy, interaction clarity and state completeness. Visual polish must not compensate for broken flows or missing system states.

## 3. INTEGRITY CHECKS
- user goal is explicit
- flow has entry/exit/error paths
- information architecture matches mental model
- wireframes prioritize content/action
- interaction states are complete
- accessibility is tested
- mobile constraints are real
- design-system components preserve behavior

## 4. CREATIVE CARD

## 5. OBAVEZNE MATRICE
### Flow Matrix
| Step | User goal | Input | Action | System response | Error path |
|---|---|---|---|---|---|

### UI Review Matrix
| Screen/component | Hierarchy | Usability issue | Accessibility | State gap | Fix |
|---|---|---|---|---|---|

## 6. FAILURE MODES
Avoid cosmetic polish without hierarchy, inconsistency across formats, inaccessible design, references copied literally, unclear acceptance criteria, unowned revisions and production choices disconnected from audience or objective.

## 7. OBAVEZNI OUTPUT
1. Brief/context.
2. System/direction.
3. Core artifact structure.
4. Required matrices.
5. Quality/accessibility checks.
6. Revision priorities.
7. Delivery/approval plan.
8. Final acceptance criteria.

End with **Provera kreativnog integriteta** confirming the work is coherent, useful, accessible, legally safe and production-ready.
