<a id="about"></a>

## Made for work that needs more than a quick answer

UPL is a model-agnostic library of detailed instructions for AI-assisted work. Prompts define the task, boundaries, evidence to inspect, likely failure modes, expected format and checks that make the final result easier to assess.

<a id="different"></a>

### A consistent standard, adapted to the task

<table width="100%">
<tr>
<td valign="top" width="50%"><strong>Clear direction</strong><br><sub>Every prompt defines a role, goal, scope and relevant non-goals so the model knows what the work includes.</sub></td>
<td valign="top" width="50%"><strong>Evidence before claims</strong><br><sub>Source priorities, confidence levels and false-positive safeguards reduce unsupported conclusions.</sub></td>
</tr>
<tr>
<td valign="top" width="50%"><strong>Useful deliverables</strong><br><sub>Concrete output formats, examples and coverage expectations turn analysis into work people can review.</sub></td>
<td valign="top" width="50%"><strong>Verification built in</strong><br><sub>Practical checks and a final quality gate are included when the task benefits from them.</sub></td>
</tr>
</table>

See the [prompt format guide](docs/prompt-format.md) for the complete specification.

**Featured prompt:** [UPL-IT-001 · Forensic Full Repository Audit](prompts/en/01-it-programming-technology/01-web-development/001-forensic-full-repository-audit.md) · [Srpski](prompts/sr/01-it-programiranje-tehnologija/01-web-development/001-forensic-full-repository-audit.md)

<a id="how-to-use"></a>

## Put a prompt to work

<table width="100%">
<tr>
<td valign="top" width="50%"><strong>01 &nbsp; Choose a task</strong><br><sub>Open the matching prompt in English or Serbian. The collection indexes organize prompts by category and subcategory.</sub></td>
<td valign="top" width="50%"><strong>02 &nbsp; Bring the instructions</strong><br><sub>Copy the prompt body into ChatGPT, Claude, Gemini, a coding agent or another capable model. Front matter is metadata and can be omitted.</sub></td>
</tr>
<tr>
<td valign="top" width="50%"><strong>03 &nbsp; Add useful context</strong><br><sub>Attach the repository, files, documents or data the task needs. The model can only assess the material and tools available to it.</sub></td>
<td valign="top" width="50%"><strong>04 &nbsp; Review the result</strong><br><sub>Narrow the scope when useful, then check findings against the source material before relying on the output.</sub></td>
</tr>
</table>

The machine-readable [`prompts.json`](indexes/prompts.json) index lists every prompt ID, title, status, version and file path.

<a id="structure"></a>

## How the repository is organized

| Location | What you will find |
|---|---|
| [`prompts/en/`](prompts/en/) and [`prompts/sr/`](prompts/sr/) | Matching prompt files in English and Serbian, grouped by category and subcategory |
| [`catalog.json`](catalog.json) | Category definitions, permanent ID namespaces and planned prompt entries |
| [`indexes/`](indexes/) | Generated prompt indexes, collection statistics and machine-readable records |
| [`docs/`](docs/) | Prompt format, ID rules, translation guidance, architecture and roadmap |
| [`scripts/`](scripts/) and [`site-src/`](site-src/) | Validation, generation and the searchable website source |

<a id="languages"></a>

## Two language editions, one stable identity

<table width="100%">
<tr>
<td valign="top" width="50%"><strong>English</strong><br><sub>Primary authoring language. Browse every published prompt in <a href="prompts/en/"><code>prompts/en/</code></a>.</sub></td>
<td valign="top" width="50%"><strong>Srpski, latinica</strong><br><sub>Matching Serbian edition in <a href="prompts/sr/"><code>prompts/sr/</code></a>. Technical terminology stays in English where that reads naturally.</sub></td>
</tr>
</table>

Both versions share the same ID, number, slug and version. A prompt is marked `stable` when every supported language version is present. Read the [translation guide](docs/translation-guide.md).

<a id="format"></a>

## Prompt files are versioned documents

Each Markdown prompt begins with YAML metadata. The permanent ID connects language editions, while the version records meaningful changes to the instructions.

<table width="100%">
<tr>
<td valign="top" width="50%"><strong>Identity and location</strong><br><sub><code>id</code>, <code>number</code>, <code>slug</code>, category and subcategory keep files addressable and organized.</sub></td>
<td valign="top" width="50%"><strong>Language and release state</strong><br><sub><code>language</code>, <code>version</code> and <code>status</code> explain which edition you are reading and whether it is ready to use.</sub></td>
</tr>
</table>

See [docs/prompt-format.md](docs/prompt-format.md) for field rules, versioning and the recommended prompt structure. See [docs/ids.md](docs/ids.md) before assigning or changing an ID.

## Help the library grow

<table width="100%">
<tr>
<td valign="top" width="50%"><strong>Improve or translate</strong><br><sub>Keep the permanent ID and filename. Update both language editions and bump the version when the instructions change.</sub></td>

</tr>

```bash
npm ci
npm run generate
npm run validate
```

Read the [contribution guide](CONTRIBUTING.md), [Code of Conduct](CODE_OF_CONDUCT.md) and [security policy](SECURITY.md).

<a id="quality"></a>

## Quality and safe use

<table width="100%">
<tr>
<td valign="top" width="50%"><strong>What validation checks</strong><br><sub>Prompt metadata, IDs, filenames, language pairs, generated indexes and internal links. It verifies repository structure, not the quality of an AI response.</sub></td>
<td valign="top" width="50%"><strong>Security work stays authorized</strong><br><sub>Use cybersecurity prompts for defensive review, secure development and systems you own or are explicitly authorized to test. See <a href="SECURITY.md">SECURITY.md</a>.</sub></td>
</tr>
</table>

Always review AI output against the source material and the requirements of your task.
