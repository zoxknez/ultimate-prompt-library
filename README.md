## Why this project exists

Most prompt collections are short one-liners that produce generic, shallow answers. Serious work - auditing a production codebase, reviewing a security boundary, analyzing a business decision - needs prompts that tell a capable AI system exactly what to examine, how to reason about evidence, how to avoid false positives and what a useful deliverable looks like.

UPL collects such prompts in one place, keeps them versioned and bilingual, and organizes them so the library can grow from dozens to thousands of prompts without reorganizing.

## What makes these prompts different

The prompts are long-form working instructions rather than one-line requests. Depending on the task, a prompt typically includes:

- a clear **role** and an explicit **goal**
- a defined **scope** and explicit **non-goals**
- an **evidence hierarchy** (what counts as proof and what is only a hypothesis)
- **severity** and **confidence** ratings
- **false-positive protection**
- a concrete **finding format**
- coverage **matrices**
- an **adversarial second pass**
- a **final quality gate**
- an **output specification**
- **real failure examples**

Not every prompt uses every element - a creative writing prompt has no need for P0-P4 severity levels. The [prompt format guide](docs/prompt-format.md) describes the recommended structure.

## Repository Structure

```text
ultimate-prompt-library/
├── prompts/
│   ├── en/                                   English prompts
│   │   ├── 01-it-programming-technology/
│   │   │   ├── README.md                     full IT index (available + planned)
│   │   │   ├── 01-web-development/
│   │   │   │   ├── README.md
│   │   │   │   └── 001-forensic-full-repository-audit.md
│   │   │   └── ...
│   │   └── 02-economics-finance-business/ … 10-creativity-design-media/
│   └── sr/                                   Serbian prompts (same subcategory folders and filenames)
├── catalog.json                              categories, subcategories and planned prompt IDs
├── indexes/                                  generated JSON indexes and statistics
├── docs/                                     format, IDs, translation, architecture, roadmap
├── scripts/                                  validation and generation tooling (Node.js)
└── .github/                                  issue/PR templates and the validation workflow
```

A prompt lives at `prompts/<language>/<category>/<subcategory>/NNN-slug.md`. The English and Serbian versions of a prompt share the same subcategory folder and filename, so switching language only changes the language (and localized category) folder. See [docs/architecture.md](docs/architecture.md) and [docs/ids.md](docs/ids.md).

## Prompt Format

Every prompt starts with YAML front matter:

```yaml
---
id: UPL-IT-035
number: 35
slug: secrets-and-credential-exposure-audit
title: Secrets & Credential Exposure Audit
category: IT, Programming & Technology
category_id: UPL-IT
subcategory: Cybersecurity
subcategory_id: cybersecurity
language: en
version: 1.0.0
status: stable
---
```

The `id` is permanent and language-independent. `status` is one of `draft`, `review`, `stable` or `deprecated`. The full specification, versioning rules and recommended body structure are in [docs/prompt-format.md](docs/prompt-format.md).

## How to Use

1. **Open a prompt** that matches your task, in the language you prefer.
2. **Copy the whole content** (the front matter is metadata and can be left out).
3. **Give it to an AI system** - a chat assistant, a coding agent or a local model.
4. **Add your context:** the repository, files, documents or data the prompt should analyze.
5. **Adjust the scope** if you only need part of the analysis (for example, one service or one module).

The library is **model-agnostic**. The prompts are written for any capable AI system - ChatGPT, Claude, Gemini, local LLMs, coding agents and others - and are not tied to any single provider. Results depend on the model, the context you provide and the tools the model can use; always review the output.

For machine use, [`indexes/prompts.json`](indexes/prompts.json) lists every available prompt with its ID, titles, status, version and file paths.

> **Security prompts:** the cybersecurity prompts are meant for defensive review, authorized testing, secure development and threat modeling. **Use security prompts only on systems you own or are explicitly authorized to test.** See [SECURITY.md](SECURITY.md).

## Contributing

Contributions are welcome: new prompts, improvements, factual corrections, translations and proposals for new areas.

- Planned prompts already have an ID - reference it in your issue or pull request.
- New prompt ideas start as an issue so an ID can be assigned through [`catalog.json`](catalog.json).
- Run `npm ci && npm run validate` before opening a pull request.

## Quality Standard

The library follows these principles:

- **Deep over generic** - prompts cover a problem thoroughly instead of listing surface-level tips.
- **Evidence over assumptions** - findings must be backed by what is actually in the material.
- **Concrete over vague** - precise checks, formats and examples instead of general advice.
- **Production-oriented** - focused on real-world failures, not textbook theory.
- **False-positive aware** - prompts actively guard against confident but wrong conclusions.
- **Model-agnostic** - usable with any capable AI system.
- **Reusable** - each prompt is a self-contained artifact that works across projects.
- **Bilingual** - English and Serbian versions are kept in step.
- **Open-source** - free to use, study, adapt and improve.

Automated checks (`npm run validate`) verify structure only: front matter, IDs, filenames, language pairs, generated indexes and internal links. They do not score prompt quality - that is the job of review.
