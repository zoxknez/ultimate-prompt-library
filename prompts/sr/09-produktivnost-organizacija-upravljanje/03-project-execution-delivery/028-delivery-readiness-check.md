# PROVERA SPREMNOSTI ZA ISPORUKU

Glavni cilj:

> Sprovedite izvršiv i auditabilan workflow za "Provera spremnosti za isporuku", sa jasnim ciljem, ownerom, pretpostavkama, zavisnostima, rizicima i review triggerima.

## 1. OPERATIVNI KONTEKST
Define objective, scope, owner, stakeholders, constraints, deadline, dependencies, current state, available capacity and success criteria.

## 2. DOMAIN STANDARD
Project execution should maintain a single view of scope, milestones, dependencies, risks, decisions and changes. Status exists to support action, not reporting theater.

## 3. INTEGRITY CHECKS
- scope has inclusions/exclusions
- milestones represent outcomes
- dependencies have owners
- risks include trigger/response
- changes update cost/time/scope
- status highlights decisions/blockers
- delivery has acceptance criteria
- retrospective produces owned actions

## 4. OPERATING CARD
```text
Objective:
Owner:
Scope:
Dependency:
Assumption:
Risk:
Decision:
Next action:
Deadline/trigger:
Success evidence:
Review date:
```

## 5. OBAVEZNE MATRICE
### Delivery Matrix
| Milestone | Outcome | Owner | Dependency | Date | Status | Acceptance |
|---|---|---|---|---|---|---|

### Risk/Change Matrix
| Item | Trigger | Impact | Owner | Response | Decision |
|---|---|---|---|---|---|

## 6. FAILURE MODES
Avoid ownerless work, hidden dependencies, vague goals, unbounded scope, excessive process, automation without controls, status reporting with no decision value and plans that ignore capacity.

## 7. OBAVEZNI OUTPUT
1. Objective and scope.
2. Owner/stakeholders.
3. Dependencies and assumptions.
4. Risks/controls.
5. Required matrices.
6. Execution sequence.
7. Review cadence.
8. Stop/change/escalation triggers.

End with **Provera operativnog integriteta** confirming every active item has ownership, a next action and a review mechanism.
