<a id="about"></a>

## Made for work that needs more than a quick answer

UPL is a model-agnostic library of detailed instructions for AI-assisted work. Prompts define the task, boundaries, evidence to inspect, likely failure modes, expected format and checks that make the final result easier to assess.

<a id="different"></a>

### A consistent standard, adapted to the task

- **Clear direction:** Every prompt defines a role, goal, scope and relevant non-goals so the model knows what the work includes.
- **Evidence before claims:** Source priorities, confidence levels and false-positive safeguards reduce unsupported conclusions.
- **Useful deliverables:** Concrete output formats, examples and coverage expectations turn analysis into work people can review.
- **Verification built in:** Practical checks and a final quality gate are included when the task benefits from them.

See the [prompt format guide](docs/prompt-format.md) for the complete specification.

**Featured prompt:** [UPL-IT-001 · Forensic Full Repository Audit](prompts/en/01-it-programming-technology/01-web-development/001-forensic-full-repository-audit.md) · [Srpski](prompts/sr/01-it-programiranje-tehnologija/01-web-development/001-forensic-full-repository-audit.md)

<a id="how-to-use"></a>

## Put a prompt to work

1. **Choose a task.** Open the matching prompt in English or Serbian. The collection indexes organize prompts by category and subcategory.
2. **Bring the instructions.** Copy the prompt body into ChatGPT, Claude, Gemini, a coding agent or another capable model. Front matter is metadata and can be omitted.
3. **Add useful context.** Attach the repository, files, documents or data the task needs. The model can only assess the material and tools available to it.
4. **Review the result.** Narrow the scope when useful, then check findings against the source material before relying on the output.

The machine-readable [`prompts.json`](indexes/prompts.json) index lists every prompt ID, title, status, version and file path.

<a id="structure"></a>

## How the repository is organized

- [`prompts/en/`](prompts/en/) and [`prompts/sr/`](prompts/sr/): matching prompt files in English and Serbian, grouped by category and subcategory.
- [`catalog.json`](catalog.json): category definitions, permanent ID namespaces and planned prompt entries.
- [`indexes/`](indexes/): generated prompt indexes, collection statistics and machine-readable records.
- [`docs/`](docs/): prompt format, ID rules, translation guidance, architecture and roadmap.
- [`scripts/`](scripts/) and [`site-src/`](site-src/): validation, generation and the searchable website source.

<a id="languages"></a>

## Two language editions, one stable identity

**English:** Primary authoring language. Browse every published prompt in [`prompts/en/`](prompts/en/).

**Srpski, latinica:** Matching Serbian edition in [`prompts/sr/`](prompts/sr/). Technical terminology stays in English where that reads naturally.

Both versions share the same ID, number, slug and version. A prompt is marked `stable` when every supported language version is present. Read the [translation guide](docs/translation-guide.md).

<a id="format"></a>

## Prompt files are versioned documents

Each Markdown prompt begins with YAML metadata. The permanent ID connects language editions, while the version records meaningful changes to the instructions.

**Identity and location:** `id`, `number`, `slug`, category and subcategory keep files addressable and organized.

**Language and release state:** `language`, `version` and `status` explain which edition you are reading and whether it is ready to use.

See [docs/prompt-format.md](docs/prompt-format.md) for field rules, versioning and the recommended prompt structure. See [docs/ids.md](docs/ids.md) before assigning or changing an ID.

<a id="contributing"></a>

## Help the library grow

- **Improve or translate:** Keep the permanent ID and filename. Update both language editions and bump the version when the instructions change.
- **Write a planned prompt:** Use the ID already reserved in `catalog.json`. Never allocate a replacement ID for a planned entry.
- **Propose a new prompt:** Start with the prompt suggestion process. An ID is assigned through the catalog after the proposal is accepted.
- **Run the project checks:** Install the tooling, regenerate derived files and validate structure and links before opening a pull request.

```bash
npm ci
npm run generate
npm run validate
```

Read the [contribution guide](CONTRIBUTING.md), [Code of Conduct](CODE_OF_CONDUCT.md) and [security policy](SECURITY.md).

## Quality and safe use

**What validation checks:** Prompt metadata, IDs, filenames, language pairs, generated indexes and internal links. It verifies repository structure, not the quality of an AI response.

**Security work stays authorized:** Use cybersecurity prompts for defensive review, secure development and systems you own or are explicitly authorized to test. See [SECURITY.md](SECURITY.md).

Always review AI output against the source material and the requirements of your task.
